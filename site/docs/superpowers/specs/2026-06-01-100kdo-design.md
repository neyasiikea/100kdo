# 100kdo（十万个干什么）产品设计文档

> 版本: 1.0 | 日期: 2026-06-01 | 状态: 设计阶段

---

## 1. 项目概要

### 1.1 项目名称

- 中文：十万个干什么
- 英文：100kdo
- 域名：100kdo.com

### 1.2 一句话定义

**给普通人的"AI领域专家一键切换"端口连接器策展平台。**

用户不需要学prompt工程，不需要理解MCP/Skill是什么——只需要在100kdo搜索或浏览自己遇到的问题领域，找到对应的工具包，一键复制粘贴到手机或网页上的AI，AI自动变成该领域的专家。

### 1.3 核心价值主张

```
普通人用AI的痛点：
  - 不知道该怎么问 (prompt engineering)
  - 不知道哪些信息源是可靠的
  - 不知道AI可以连接哪些权威数据库
  - 找不到现成的MCP/Skill/API连接器

100kdo提供：
  - 按领域策展的"端口连接器"目录
  - 每个领域 = 权威信息源 + 现成连接器 + 专家prompt + 场景工作流
  - 一条龙：搜 → 找到 → 复制 → 粘贴到AI → 获得专家级回复
```

### 1.4 100kdo 不是什么

| ❌ 不是 | ✅ 是 |
|---------|------|
| AI应用导航站（如ai-bot.cn） | 领域工具包的策展与分发 |
| MCP/Skill市场（需要技术背景） | 零门槛"拿来就用" |
| Prompt教学网站 | 成品交付，不教原理 |
| Vibe coding工具市场 | 排除开发者工具 |
| 又一个AI聊天产品 | 工具包的策展层，不替代AI |

## 2. 产品定位

### 2.1 双分支分布模型

100kdo 设计为**人机双读**——同时服务于两个分发路径：

```
分支1：AI自主发现（被动）
  用户 → 在DeepSeek/ChatGPT中提问
     → AI联网搜索，抓取到100kdo的工具包页面
       → AI读取结构化数据，自动加载端口连接器
         → 用户无感获得专家级回复

分支2：用户主动使用（主动）
  用户 → 打开100kdo → 搜索/浏览领域
     → 找到工具包 → 复制/一键跳转
       → 粘贴到AI → AI获得专家能力
         → 用户获得专家级回复
```

**双分支的技术要求：**
- 每个工具包页面必须是自包含的结构化数据（Schema.org / JSON-LD）
- SEO友好的内容结构，确保AI搜索引擎可抓取
- 同时满足人类可读的画面展示

### 2.2 目标用户

- 使用DeepSeek、ChatGPT、Gemini、豆包、Kimi、通义千问等网页/App版AI的普通用户
- 使用Cherry Studio、ChatBox、NextChat、LobeChat、Open WebUI等轻度agent平台的进阶用户
- **明确排除**：使用Codex、Claude Code、Cursor Agent、WorkBuddy等vibe coding工具的开发者

### 2.3 两个场景层级

| 场景 | 用户画像 | AI平台 | 工具包形态 | 交互方式 |
|------|---------|--------|-----------|---------|
| **L1 纯聊天AI** | 手机App/网页用户 | DeepSeek / ChatGPT / Gemini / 豆包 / Kimi / 通义千问 / 文心一言 | Prompt文本 + 场景工作流 + 数据源链接 | 复制 → 粘贴 → 开始对话 |
| **L2 轻度Agent** | 进阶用户 | Cherry Studio / ChatBox / LobeChat / Open WebUI / NextChat | L1内容 + Skill配置 + MCP端点 + Agent预设 | 一键导入 / 链接安装 |

## 3. 工具包（Toolkit）数据模型

### 3.1 三层架构

```
┌─────────────────────────────────────────────┐
│  L1 · 场景工作流层                            │
│  引导用户："这个问题怎么拆解为具体场景"          │
│  每个场景自动关联对应端口                       │
├─────────────────────────────────────────────┤
│  L2 · 专家Prompt层                            │
│  告诉AI："你是谁、怎么说话、调用哪些端口"        │
│  内置端口连接器调用指令                         │
├─────────────────────────────────────────────┤
│  L3 · 权威信息端口层 ← 100kdo的核心价值         │
│  权威信息源 + 现成连接器 (MCP/Skill/API/GPTs)   │
│  标注：验证状态、适用平台、贡献来源              │
└─────────────────────────────────────────────┘
```

### 3.2 L3 端口连接器详细字段

每个端口连接器包含：

| 字段 | 说明 | 示例 |
|------|------|------|
| 权威信息源名称 | 数据库/机构名称 | WHO 儿童生长标准数据库 |
| 信息源URL | 数据入口地址 | who.int/tools/child-growth-standards |
| 端口类型 | 连接方式 | REST API / MCP Server / Skill / GPTs Action / 静态数据 |
| 连接器名称 | 现成的连接器标识 | who-growth-mcp |
| 连接器地址 | 获取/安装地址 | GitHub / npm / 官网链接 |
| 验证状态 | 可用性确认 | ✅已验证 / ⚠️待验证 / 📦社区贡献 |
| 适用平台 | 可在哪些AI工具中使用 | Cherry Studio / LobeChat / GPTs |
| 贡献者 | 策展/贡献来源 | 100kdo策展 / 社区贡献 |

### 3.3 端口类型分类

| 端口类型 | 说明 | 适用场景 |
|---------|------|---------|
| **REST API** | 直接HTTP接口调用 | 实时数据查询（天气、股价、航班） |
| **MCP Server** | Model Context Protocol服务器 | Cherry Studio / LobeChat / Open WebUI |
| **Skill 文件** | 可安装的技能配置文件 | Cherry Studio / 文档型通用 |
| **GPTs Action** | OpenAI GPTs自定义动作 | ChatGPT Plus |
| **静态数据** | 整理好的结构化知识文档 | 所有平台通用 |
| **网页抓取** | 指向公开数据页面的抓取指令 | DeepSeek / 通用 |

## 4. 产品形态

### 4.1 总体定位

介于 **hao123（目录型门户）** 和 **Google（搜索型门户）** 之间，融合两种形态：

- **浏览模式**：领域分类树 → 层层深入找到工具包（像hao123按主题分类）
- **搜索模式**：自然语言搜索"怎么处理孩子发烧" → 直接匹配到对应工具包（像Google但只搜工具包）
- **发现模式**：热门工具包 / 最新策展 / 编辑推荐

### 4.2 核心页面

| 页面 | 功能 |
|------|------|
| **首页** | 搜索框 + 领域分类入口 + 热门推荐 + 最新工具包 |
| **领域页** | 该领域的所有工具包列表，带简介预览 |
| **工具包详情页** | 完整的L1/L2/L3内容，复制按钮，平台跳转按钮 |
| **搜索页** | 自然语言搜索结果，突出匹配度 |
| **关于页** | 100kdo是什么，使用指南 |

## 5. 交付方式

### 5.1 策略：混合方案（方案C）

按平台分级交付：

| 平台类型 | 交付方式 | 优先级 |
|---------|---------|--------|
| **支持DeepLink的AI** | 一键直达，prompt自动填入 | 有则优先 |
| **不支持DeepLink的AI** | 复制工具包 + 提示打开对应平台 | 所有平台 |
| **移动端App** | 通用Share Sheet + 复制 | 移动优先 |
| **Cherry Studio等** | 配置导入链接（一键安装skill/MCP） | 进阶用户 |

### 5.2 交付按钮设计

每个工具包详情页提供：

1. **主按钮**：「复制工具包」—— 一键复制完整的L1+L2+L3到剪贴板
2. **平台按钮**：一排AI平台快捷图标，点击跳转到对应平台
3. **分项复制**：允许单独复制Prompt、单独复制某个端口的连接器配置
4. **分享**：生成工具包分享链接，方便传播

### 5.3 复制内容格式

复制工具包时，剪贴板内容是**AI可直接消化的结构化文本**：

```
你现在是以下角色：[专家Prompt内容]

在回答时，请使用以下权威数据源：
- [端口名称]：[信息源说明]（连接方式：[REST API/MCP/Skill/...]）
- [端口名称]：[信息源说明]（连接方式：[REST API/MCP/Skill/...]）

常见问题处理流程：
1. [场景1] → 使用端口 [xxx]
2. [场景2] → 使用端口 [xxx]
```

## 6. 技术约束

### 6.1 人机双读的数据结构

每个工具包页面必须输出：

- **可见层**（HTML）：人类可读的完整内容
- **结构化层**（JSON-LD / Schema.org）：AI可解析的数据
- **Meta层**：SEO元数据，确保AI搜索引擎可索引

### 6.2 技术栈偏好（后续实现阶段确定）

- 前端：Next.js (App Router) + TypeScript
- 样式：Vanilla CSS / CSS Modules
- 部署：Cloudflare Pages
- 数据：从静态文件/Markdown开始，后续按需引入数据库
